# ユーザー登録

パス: `/users/new`

## ユーザーストーリー（Why）

- 研究者が、初回ログイン時にユーザーIDを決めることで、他のユーザーからプロジェクトに招待してもらえるようにしたい（CESCHI-204、理由は推測）
- 研究者が、表示される名前を決めることで、共同作業の相手に自分だと分かるようにしたい（推測、確信度: 高）

## 外部仕様（What）

- 「ユーザーID」と「名前」の入力欄と、「保存」ボタンを表示する
  - ほかの画面へのリンク（プロジェクト一覧へ戻るリンクなど）は表示しない
- 入力欄の初期値は、今のユーザーIDと名前とする
  - 初めてログインしたときは、ユーザーID は空、名前は Google アカウントの名前とする
  - ユーザーID の入力欄が空のときは、「carble」を薄く表示する（プレースホルダー）
- ユーザーID の入力欄に「利用可能な文字: 半角英数およびハイフン（-）、アンダースコア（_）」と案内を表示する
- ユーザーID は入力するたびに確かめ、問題があれば入力欄の下に表示する
  - **IF** 3 文字未満または 30 文字を超える場合、「3文字以上30文字以下で設定してください」と表示する
  - **IF** 半角英数・ハイフン・アンダースコア以外の文字を含む場合、「利用できない文字が含まれています」と表示する
  - **IF** 他のユーザーが使っているユーザーID の場合、「既に使われています」と表示する
    - 英字の大文字と小文字は区別しない（「Carble」は「carble」と同じユーザーID とみなす）
  - **WHILE** 他のユーザーが使っているかを確かめている間は、入力欄に読み込み中のアイコンを表示する
- **IF** 名前が空の場合、「必須です」と表示する
- **WHILE** 入力に問題がある間は、「保存」ボタンを押せない
- **WHEN** 「保存」を押すと、ユーザーIDと名前を保存し、[プロジェクト一覧](project-list.md)に遷移する
  - ユーザーID の英字の大文字は、小文字にして保存する

## 補足情報

### 実装との乖離

- 初めてログインしたとき、ユーザーID の入力欄に触れずに「保存」を押せてしまう（未入力を問題として扱わない）。押すとユーザーID の無いまま保存し、プロジェクト一覧に遷移しようとして、この画面に戻される。メッセージは表示しない（[ISSUES.md](../../ISSUES.md#初回のユーザー登録でユーザーidを入れずに保存できる)）
