# CESCHI-212 プロジェクトに他のユーザーを招待し、共同で編集する

## 背景（なぜ）

- ユーザー登録（CESCHI-204）で、各ユーザーは自分のプロジェクトだけを見るようになった。次に、プロジェクトを複数人で共同編集できるようにする必要があった
- 研究者からは、複数のユーザーが 1 つのプロジェクトに記録を寄せる場合に、誰が何を寄せたか（貢献者）を管理し、表示できるようにしたいという要望が出ていた。共同編集は、その前提として位置づけられた
- メンバーを加える方法として、オーナーがユーザーIDを入力して加える形、利用者が参加を申し出てオーナーが承認する形、招待のリンクを配る形を比べた。オーナーが確実に権限を管理できることから、オーナーがユーザーIDで加える形に決めた
- ただし、加えるだけだと、加えられる側のプロジェクト一覧に、望まないプロジェクトが勝手に増えてしまう。そこで、加えられる側が参加か拒否かを選べる「招待」の形にした。研究者もこの形を了承した

## 決めたこと

- オーナーは、ユーザーIDを入力して他のユーザーを招待する。存在しないユーザーIDでは招待できない
- 招待されたユーザーは、プロジェクト一覧で招待に気づき、参加か拒否かを選ぶ
  - 参加すると「編集者」になり、カードを操作できる
  - 拒否すると、招待は消え、オーナーの一覧からも消える
- メンバーの一覧の表示と操作（招待・削除）は、オーナーだけができる
- 編集者は、ほかのユーザーの招待、プロジェクトの権限の設定、プロジェクトの削除はできない。自分からプロジェクトを抜けることもできない
- プロジェクト一覧には、自分がオーナーのプロジェクトと、編集者として参加しているプロジェクトだけを表示する
